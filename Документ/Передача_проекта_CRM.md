# Передача проекта CRM другому ИИ или разработчику

Дата актуализации: 17 апреля 2026.

## 1. Кратко о проекте

Это локальная CRM для одного менеджера на одном ПК. Приложение работает через локальный сервер и браузер:

- адрес: `http://localhost:3000`;
- запуск: `npm run dev`;
- база данных: `data/crm.sqlite`;
- резервные копии: `data/backups`;
- SMTP-пароль хранится только в `.env.local`;
- Firebase уже удалён после одноразового импорта реальных данных.

Главная архитектурная идея: не облачная CRM, а автономная локальная программа, где фронтенд общается с локальным Express API, а сервер пишет данные в SQLite.

## 5. Переменные окружения

Файл `.env.local` должен быть создан локально и не должен попадать в репозиторий.

Пример:

```env
SMTP_HOST="smtp.yandex.ru"
SMTP_PORT="465"
SMTP_SECURE="true"
SMTP_USER="manager@example.com"
SMTP_PASSWORD="YANDEX_APP_PASSWORD"
SMTP_FROM_NAME="CRM"
```

Важно: старый пароль приложения Яндекса, который раньше был в исходном коде, нужно считать скомпрометированным. Использовать только новый пароль приложения.

## 6. Локальный API

Основные endpoints:

- `GET /api/health` - проверка, что сервер жив.
- `/api/clients` - клиенты.
- `/api/contracts` - договоры и связанные брони.
- `/api/settings` - общие настройки.
- `/api/organizations` - реквизиты организаций.
- `/api/html-templates` - HTML-шаблоны документов.
- `/api/send-email` - отправка email через SMTP из `.env.local`.
- `/api/backups` - создание резервной копии SQLite.
- `/api/email-settings` - SMTP-настройки без пароля.

Firebase endpoint импорта удалён, потому что импорт уже выполнен и Firebase-зависимости больше не нужны.

## 7. База данных и правила данных

База создаётся автоматически при старте сервера:

```text
data/crm.sqlite
```

Основные сущности:

- клиенты;
- договоры;
- брони;
- настройки;
- организации;
- HTML-шаблоны;
- метаданные шаблонов;
- история email.

Единые ID услуг:

- `gb-bath`;
- `gb-furako`.

Проверка пересечения броней выполняется на сервере. Конфликт есть, если:

```text
objectId совпадает
status не равен cancelled
newStart < existingEnd
newEnd > existingStart
```

## 8. Шаблоны документов

Шаблоны хранятся в SQLite в HTML-формате и редактируются через интерфейс CRM.

Текущее состояние:

- `invoice` настроен и перенесён из готового DOCX в чистый HTML.
- `act` настроен и перенесён из готового DOCX в чистый HTML.
- Для менеджера в договоре используется единый пункт "Счёт + акт": первая страница - счёт, вторая страница - акт.
- `gb_cottage` был настроен ранее.
- `cc_cottage` настроен и перенесён из готового DOCX в чистый HTML; при переносе восстановлена автонумерация Word и очищены лишние пробелы вокруг переменных.
- Остальные шаблоны могут показываться как "Не настроен" и требуют заполнения перед использованием.

Важные правила для дальнейшей разработки:

- Не возвращать fallback на чужой шаблон. Если нужный шаблон не настроен, документ должен честно показывать ошибку.
- Перед перезаписью шаблона сервер делает бэкап старой версии в `data/backups/templates`.
- Подстановка переменных должна экранировать HTML-спецсимволы, чтобы данные клиента не ломали таблицы.
- Не навязывать всем таблицам `width: 100%`, иначе счета и банковские таблицы снова "поедут".
- Для печатной области ориентироваться на A4 примерно `794px x 1123px` с полями около `20mm`.

Формат переменных:

```text
{client_name}
{contract_number}
{invoice_number}
{doc_date}
{service_name}
{service_qty}
{service_price}
{service_total}
{vat_amount}
{total_words_only}
```

Полный список переменных смотреть в `src/utils/templateVariables.ts`.

## 9. Что важно знать про Jodit

Редактор HTML-шаблонов использует `jodit-react`.

Уже исправленная проблема: при сохранении после ручных правок Jodit иногда падал с ошибкой:

```text
Cannot read properties of undefined (reading 'value')
```

Причина: код читал `jodit.value`, а внутренний native editor value иногда временно отсутствует.

Текущий подход:

- сначала брать `jodit.editor.innerHTML`;
- потом пробовать `jodit.getEditorValue()`;
- если Jodit временно не готов, брать последнюю черновую версию из `latestContentRef`.

При дальнейших правках редактора не возвращаться к прямому чтению `jodit.value`.

## 10. Email

Email отправляется сервером через `nodemailer`.

Пароль:

- не хранить в базе;
- не передавать во фронтенд;
- брать только из `.env.local`.

Если снова появится ошибка вида:

```text
connect ECONNREFUSED 77.88.21.158:465
```

Сначала проверить VPN, фаервол, антивирус, роутер и доступность портов `465`/`587`. В прошлый раз причиной был VPN, после отключения VPN письмо ушло.

- ручной бэкап SQLite через интерфейс настроек;
- бэкап HTML-шаблона перед его перезаписью.

## 12. Оставшаяся audit-проблема

Осталась известная проблема с пакетом:

```text
xlsx
```

`npm audit fix` не предлагает исправления для текущего пакета.

Варианты дальнейшего решения:

- оставить временно как есть, потому что программа локальная на одном ПК;
- заменить `xlsx` на `exceljs`;
- убрать Excel-экспорт, если он не нужен;
- переписать только экспорт шахматки на другую библиотеку.

Рекомендуемый путь: заменить `xlsx` на `exceljs` отдельным этапом, после проверки, где именно используется Excel-экспорт.

## 15. Что не делать без крайней необходимости

- Не возвращать Firebase.
- Не хранить SMTP-пароль во фронтенде, базе или шаблонах.
- Не удалять `data/crm.sqlite` без бэкапа.
- Не отключать серверную проверку пересечения броней.
- Не делать общий `table { width: 100% }` для документов.
- Не использовать чужой шаблон вместо отсутствующего нужного шаблона.
- Не перезаписывать шаблоны без бэкапа.
