# Анализ архитектуры и взаимодействия файлов CRM

Данный проект представляет собой полнофункциональную CRM-систему, построенную на современном стеке технологий. Программа объединяет возможности управления клиентами, договорами, бронированиями (в формате «шахматки»), задачами и автоматического формирования документов.

## 🏗 Общая архитектура

Проект реализован как **Monolithic Full-Stack** приложение:
- **Backend**: Node.js + Express + SQLite.
- **Frontend**: React + Vite + TypeScript.
- **База данных**: SQLite (через `better-sqlite3`), хранящая как структурированные данные, так и гибкие JSON-объекты.

## 📂 Структура проекта и взаимодействие файлов

### 1. Серверная часть (Backend)
- **`server.ts`**: Главная точка входа. 
    - Настраивает Express-сервер.
    - В режиме разработки подключает Vite как middleware.
    - Определяет все API-эндпоинты (`/api/...`).
    - Управляет авторизацией и отправкой почты через `nodemailer`.
- **`server/localDatabase.ts`**: Сердце данных.
    - Инициализирует схему БД (таблицы: `clients`, `contracts`, `bookings`, `tasks` и др.).
    - Реализует логику проверки конфликтов бронирования (чтобы один номер не заняли дважды).
    - Обрабатывает транзакции (например, одновременное сохранение договора и всех его бронирований).
- **`server/authService.ts`**: Система безопасности.
    - Управляет пользователями (менеджерами), их ролями (`admin`/`manager`) и сессиями.
- **`server/backupService.ts`**: Надежность.
    - Отвечает за автоматическое и ручное резервное копирование в локальные папки и облачные хранилища.

### 2. Клиентская часть (Frontend)
- **`src/main.tsx` & `src/App.tsx`**:
    - `main.tsx` — точка входа React.
    - `App.tsx` — основной каркас UI. Содержит навигацию (Шахматка, Клиенты, Договоры, Задачи, Настройки) и логику переключения видов.
- **`src/services/localApi.ts`**:
    - Слой абстракции для общения с сервером. Содержит типизированные функции для вызова API (например, `contractApi.save()`).
- **`src/components/`**:
    - **`chessboard/`**: Реализация интерактивной сетки бронирований.
    - **`contracts/` & `clients/`**: Сложные формы и таблицы для управления сущностями.
    - **`ui/NotificationCenter.tsx`**: Система уведомлений о заездах/выездах и просроченных задачах.
- **`src/context/`**:
    - `AuthContext`: Хранит данные о текущем залогиненном менеджере и его правах.
    - `ToastContext`: Управляет всплывающими уведомлениями (успех/ошибка).

## 🔄 Принцип работы программы

### 1. Жизненный цикл запроса
1. Пользователь совершает действие (например, создает бронирование в Шахматке).
2. Компонент вызывает метод из `src/services/localApi.ts`.
3. `localApi` отправляет HTTP-запрос (POST/PUT/GET) на сервер (Express).
4. Сервер проверяет права доступа (`requireAuth` или `requireAdmin`).
5. Если проверка пройдена, вызывается метод из `localDb` (в `server/localDatabase.ts`).
6. `localDb` выполняет SQL-запросы к файлу `data/crm.sqlite`.
7. Результат возвращается по цепочке обратно во Frontend, где React обновляет состояние и перерисовывает интерфейс.

### 2. Работа с документами
Система использует библиотеку `@pdfme`. 
- В настройках менеджер может редактировать шаблоны документов.
- При нажатии «Печать» в договоре, Frontend собирает данные клиента и договора, накладывает их на JSON-шаблон и генерирует готовый PDF прямо в браузере или на сервере.

### 3. Безопасность и отказоустойчивость
- **Авторизация**: Доступ к API защищен Bearer-токенами. Пароли в БД хранятся в виде хэша с солью.
- **Конфликты**: При попытке сохранить бронирование сервер проверяет пересечение дат в таблице `bookings`. Если объект занят, возвращается ошибка 409 (Conflict).
- **Бэкапы**: При выходе из системы (Logout) программа предлагает создать резервную копию, которая отправляется в облако, обеспечивая сохранность данных.

## 🛠 Ключевые технологии
- **TypeScript**: Обеспечивает строгую типизацию во всем проекте.
- **Tailwind CSS**: Используется для стилизации интерфейса.
- **Framer Motion (`motion`)**: Плавные анимации интерфейса.
- **Date-fns**: Мощная работа с датами (особенно важно для шахматки).
- **Lucide-React**: Библиотека иконок.

Проект спроектирован как надежное локальное решение с возможностью облачной синхронизации данных, что делает его идеальным для малого и среднего бизнеса в сфере гостеприимства.
