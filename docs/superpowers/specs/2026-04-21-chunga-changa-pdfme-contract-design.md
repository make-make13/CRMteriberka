# PDFMe Package Design: Chunga-Changa

**Date:** 2026-04-21

## Goal

Собрать для Чунга-Чанги единый PDFMe-пакет документов, который формируется одним действием из карточки договора и содержит:

1. договор Чунга-Чанга;
2. счёт на следующей странице;
3. акт на следующей странице.

Во всех частях пакета используется один и тот же номер договора. Префикс `ЧЧ` закреплён в самих страницах шаблона, а подставляется только номер.

## Existing Context

- В проекте уже есть рабочий PDFMe-шаблон счёта/акта `invoice_pdfme`, сохранённый в SQLite и вручную доведённый пользователем.
- Для Чунга-Чанги уже собран отдельный 4-страничный PDFMe-договор, но он пока не сохранён в базе и не совпадает с новой пакетной моделью.
- Редактор PDFMe открывает шаблоны из SQLite, а при отсутствии записи использует кодовый дефолт.
- Пользователь хочет считать отдельный PDFMe-счёт вспомогательной исторической заготовкой, а не основным способом выпуска документов.

## Chosen Approach

Использовать текущий stable id `cc_contract_pdfme`, но переопределить его смысл как пакет Чунга-Чанга:

- страницы 1-4: договор и допсоглашение Чунга-Чанга;
- страница 5: счёт;
- страница 6: акт.

Счёт и акт не рисуются заново с нуля. Их страницы копируются из уже существующего PDFMe-счёта/акта, чтобы сохранить текущую ручную верстку пользователя.

## Document Structure

### Pages 1-4

- существующие страницы договора и допсоглашения Чунга-Чанга;
- заголовки и текст оставляют префикс `№ЧЧ` в самом шаблоне;
- в переменные подставляется только числовой номер договора.

### Page 5

- текущая страница счёта из `invoice_pdfme`;
- заголовок страницы должен использовать номер договора того же пакета;
- префикс `ЧЧ` остаётся текстом шаблона.

### Page 6

- текущая страница акта из `invoice_pdfme`;
- заголовок страницы использует тот же номер договора;
- префикс `ЧЧ` остаётся текстом шаблона.

## Numbering Strategy

- В пакет передаётся один номер договора.
- На странице договора используется вид `Договор №ЧЧ{номер}`.
- На странице счёта используется вид `Счёт №ЧЧ{номер}`.
- На странице акта используется вид `Акт №ЧЧ{номер}`.
- Никакой отдельной нумерации счёта или акта не вводится.

## Data Strategy

### Shared across the whole package

- `contract_number`
- `sign_date`
- `date_in`, `date_out`
- `date_in_short`, `date_out_short`
- `time_in`, `time_out`
- `client_name`
- `client_name_short`
- `total`
- `prepayment`
- `vat_amount`

### Contract-only areas

- паспортные данные;
- телефон и email;
- реквизиты сторон;
- подписи договора и допсоглашения.

### Invoice/Act pages

- используются уже существующие поля `invoice_header`, `act_header`, `service_*`, `act_service_*`, `qty_words`, `act_qty_words`, `act_total_words_only`.
- при сборке пакета эти поля должны быть пересчитаны под `№ЧЧ{номер}`.

## Designer Behavior

- В редакторе PDFMe пакет должен открываться как единый 6-страничный документ.
- `multiVariableText` должен показывать тестовые значения переменных, а не пустые строки.
- Если пакет ещё не сохранён, дефолт должен строиться на основе текущего `invoice_pdfme`, чтобы в страницы счёта и акта попадала последняя пользовательская верстка.

## Integration Points

- `src/utils/pdfmeTemplateIds.ts`: описание шаблона как пакетного документа.
- `src/utils/pdfmeTemplates.ts`: сборка package template из договора ЧЧ и страниц счёта/акта.
- `src/utils/pdfmeDocumentGenerator.ts`: формирование единого PDF-пакета.
- `src/components/settings/PdfmeTemplateEditorModal.tsx`: загрузка пакетного шаблона с подмешиванием текущего `invoice_pdfme`.
- `src/components/contracts/ContractModal.tsx`: выдача пользователю одного действия `PDFMe: Пакет ЧЧ`.
- `scripts/auditFixesTest.ts`: тесты на структуру package template и на подстановку номера в договор/счёт/акт.
